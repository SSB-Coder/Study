How to Read This Report

Notation, conventions, and the two honesty rules this report follows.

This report is built like a staircase. Chapters 01–03 cover the basic neural network ideas that have existed since the 1950s–80s: a single neuron, a network of neurons, and how a network "learns" by adjusting numbers. Notation used throughout

Plain italic letters like \(x\) or \(w\) are single numbers (scalars). Bold lowercase letters like \(\mathbf{x}\) are lists of numbers (vectors). Bold uppercase letters like \(\mathbf{W}\) are grids of numbers (matrices) — a matrix is just a rectangular table of weights. A superscript in parentheses, like \(\mathbf{W}^{(l)}\), means "this belongs to layer \(l\)" — it is a label, not an exponent. Every equation in this report is followed by a small "What does each symbol mean?" box, so you never have to guess.

Two honesty rules this report follows

Rule 1 — Show your work. Every equation is the real, published equation from the original research (cited in the footer), not a simplification that secretly changes the meaning.

Rule 2 — Don't invent numbers. Companies like Anthropic, OpenAI, and Google do not publish the exact size or weight values of their flagship models. Where a number is a company's own published figure, it is marked published. Where a number is industry speculation or a rough estimate rather than a confirmed fact, it is marked unconfirmed and labelled as such in the text — this report will never present a guess as if it were a fact.

Chapter 01

The Atom of Intelligence: One Neuron

Weights, biases, and the tiny calculation that everything else is built from.

Picture a tiny machine. It has a few "dials," one for every number you feed into it. Each dial decides how much that particular input matters. The machine multiplies each input by its dial setting, adds everything up along with one extra "starting offset" number, and then squeezes the result through a simple shaping function to decide how strongly to respond. That's it. That tiny machine is an artificial neuron, and almost the entire rest of this report is just "what happens when you connect millions or billions of these together, and arrange them cleverly."

In that description: the dial settings are the weights, the starting offset is the bias, the machine itself is the neuron, and the wires carrying numbers into the machine are the connections. A weight is nothing more than a single number that says "how much should I listen to this particular input?" A large positive weight means "listen closely and respond in the same direction"; a weight near zero means "mostly ignore this"; a large negative weight means "listen closely, but respond in the opposite direction."

Equation 1.1 — The neuron's weighted sum (the "pre-activation")
\[ z = w_1 x_1 + w_2 x_2 + \dots + w_n x_n + b \;=\; \sum_{i=1}^{n} w_i x_i + b \;=\; \mathbf{w}^{\top}\mathbf{x} + b \]
What does each symbol mean?
\(x_1,\dots,x_n\)
The \(n\) input numbers arriving at this neuron — these could be raw data (like pixel brightness) or the outputs of other neurons.
\(w_1,\dots,w_n\)
The weights — one learnable number per input, controlling how much that input influences this neuron.
\(b\)
The bias — one extra learnable number that shifts the result up or down, independent of any input. Think of it as the neuron's default "mood" before it has seen anything.
\(\mathbf{w}^{\top}\mathbf{x}\)
The same sum written compactly as a dot product of the weight vector \(\mathbf{w}=(w_1,\dots,w_n)\) and the input vector \(\mathbf{x}=(x_1,\dots,x_n)\).
\(z\)
The result — often called the pre-activation or logit. It is just a single number, which can be anything from very negative to very positive.

On its own, \(z\) is just a weighted sum — useful, but limited to drawing a single straight line through the data. To let the neuron make more interesting, non-linear decisions, \(z\) is passed through an activation function:

Equation 1.2 — The neuron's output (the "activation")
\[ a = f(z) \]
What does each symbol mean?
\(f\)
The activation function — a fixed, non-linear shaping function (examples below). It is chosen by the designer and does not change during training.
\(a\)
The neuron's final output, sometimes also written \(h\) for "hidden activation." This is the number that gets sent onward to the next neurons it is connected to.

A worked example: "Should I go for a run today?"

Suppose a neuron looks at three inputs, each scaled to a number between 0 and 1: how comfortable the temperature is (\(x_1=0.9\)), how much free time you have (\(x_2=0.4\)), and your current energy level (\(x_3=0.7\)). Imagine training has set the weights to \(w_1=1.2,\ w_2=0.3,\ w_3=0.8\) and the bias to \(b=-0.9\). Plugging into Equation 1.1:

Worked calculation
\[ z = (1.2)(0.9) + (0.3)(0.4) + (0.8)(0.7) + (-0.9) = 1.08 + 0.12 + 0.56 - 0.9 = 0.86 \]

Notice that temperature has the largest weight (1.2), so it dominates the decision — exactly what "weight" means in everyday English too. Passing \(z=0.86\) through the sigmoid activation (defined next) gives \(a = \sigma(0.86) \approx 0.70\), which we might read as "70% likely to go for a run." Every number in this calculation — \(w_1, w_2, w_3, b\) — started out random and was nudged into these values by the training process described in Chapter 03.

Activation functions: how a neuron "fires"

The activation function is what makes a network capable of learning curves, edges, and complex patterns instead of just straight lines. Below are the functions referenced later in this report, from the historical original to the ones used inside modern Transformers.

Equation 1.3 — Step function (the original 1958 Perceptron)
\[ f(z) = \begin{cases} 1 & \text{if } z \ge 0 \\ 0 & \text{if } z < 0 \end{cases} \]
What does each symbol mean?
\(z\)
The weighted sum from Equation 1.1.
output
A hard "yes" (1) or "no" (0) — the neuron either fires or it doesn't, with nothing in between. This makes the function impossible to fine-tune smoothly, which is why it was replaced for training larger networks.
Equation 1.4 — Sigmoid (logistic) function
\[ \sigma(z) = \frac{1}{1+e^{-z}} \]
What does each symbol mean?
\(e\)
Euler's number, \(\approx 2.71828\) — the base of the natural exponential, a fixed mathematical constant.
\(\sigma(z)\)
A smooth "S-shaped" curve that squeezes any real number into the open range \((0,1)\) — useful for representing probabilities. Very negative \(z\) gives a value near 0; very positive \(z\) gives a value near 1; \(z=0\) gives exactly 0.5.
Equation 1.5 — ReLU (Rectified Linear Unit)
\[ \text{ReLU}(z) = \max(0, z) \]
What does each symbol mean?
\(\max(0,z)\)
"Whichever is larger, 0 or \(z\)." In practice: if \(z\) is negative, output 0; if \(z\) is positive, pass it through unchanged. This was the activation used in the original 2017 Transformer's feed-forward layers, and is still the easiest to compute.
Equation 1.6 — SiLU / Swish (the basis of every modern LLM's activation)
\[ \text{SiLU}(z) = z \cdot \sigma(z) = \frac{z}{1+e^{-z}} \]
What does each symbol mean?
\(\sigma(z)\)
The sigmoid function from Equation 1.4.
\(\text{SiLU}(z)\)
Also written \(\text{Swish}(z)\) — a smooth curve that behaves like ReLU for large positive \(z\) (passes the value through) but, unlike ReLU, dips slightly negative for small negative \(z\) instead of flattening to exactly zero. This small change has been found to noticeably improve training, and is the building block of the SwiGLU function used by Llama, DeepSeek, Qwen, and most other modern models — see Chapter 7.
Why bother with a shaping function at all?

If every neuron only ever computed \(z = \mathbf{w}^\top\mathbf{x}+b\) with no activation function, then stacking layers would be mathematically pointless — a chain of weighted sums is still just one big weighted sum, no matter how many layers you stack. The non-linear activation function is what lets each additional layer learn something genuinely new, which is what makes "deep" learning deep.

Chapter 02

Stacking Neurons Into Networks

Layers, fully-connected weight matrices, and where the word "parameters" comes from.

A single neuron can only separate data with one straight line — useful for very simple yes/no problems, but not enough to recognise a face or write a sentence. The fix, discovered in the 1980s, is simple: connect many neurons together in layers. The outputs of one layer become the inputs to the next. A network built this way — where every neuron in a layer connects to every neuron in the previous layer — is called a fully connected network or Multi-Layer Perceptron (MLP).

Equation 2.1 — One layer of a fully connected network
\[ \mathbf{a}^{(l)} = f\!\left(\mathbf{W}^{(l)}\mathbf{a}^{(l-1)} + \mathbf{b}^{(l)}\right), \qquad \mathbf{a}^{(0)} = \mathbf{x} \]
What does each symbol mean?
\(l\)
The layer number, counting from the input (\(l=0\)) toward the output.
\(\mathbf{a}^{(l-1)}\)
The vector of activations (outputs) from the previous layer — a list of \(n_{l-1}\) numbers. For the very first layer, this is just the raw input \(\mathbf{x}\).
\(\mathbf{W}^{(l)}\)
The weight matrix for layer \(l\) — a grid of numbers with \(n_l\) rows (one per neuron in this layer) and \(n_{l-1}\) columns (one per input coming from the previous layer). The entry \(W^{(l)}_{ij}\) is the single weight on the connection from neuron \(j\) in layer \(l\!-\!1\) to neuron \(i\) in layer \(l\) — exactly one teal or amber line in Figure 2.1.
\(\mathbf{b}^{(l)}\)
The bias vector for layer \(l\) — one bias number per neuron in this layer.
\(f(\cdot)\)
The activation function from Chapter 1, applied to every entry of the vector independently (so each neuron in the layer fires on its own).
\(\mathbf{a}^{(l)}\)
The output of this layer — \(n_l\) numbers, which become the input to layer \(l\!+\!1\), and so on until the final layer produces the network's prediction, often written \(\hat{\mathbf{y}}\).

Where "parameters" comes from

Every entry of every \(\mathbf{W}^{(l)}\) and every \(\mathbf{b}^{(l)}\) — across every layer — is one adjustable number. Collectively, all of these numbers are called the parameters of the network, and "weights" is often used loosely to mean "all the parameters," even though strictly the biases are a separate (much smaller) group. A single fully connected layer going from \(n_{l-1}\) neurons to \(n_l\) neurons contains \(n_l \times n_{l-1}\) weights plus \(n_l\) biases. When people say a model "has 70 billion parameters," they mean: if you printed out every single one of these numbers from every \(\mathbf{W}\) and \(\mathbf{b}\) in the entire network and counted them, you would count 70 billion. That is genuinely all the phrase means — there is no extra hidden complexity.

Worked example: a full forward pass through Figure 2.1

Let the input be \(\mathbf{x}=(1,\ 0.5)\). Suppose training has produced these values (small, arbitrary numbers for illustration):

Numbers for this example
\[ \mathbf{W}^{(1)} = \begin{pmatrix} 0.4 & -0.2 \\ 0.1 & 0.3 \\ -0.5 & 0.6 \end{pmatrix},\quad \mathbf{b}^{(1)} = \begin{pmatrix} 0.1 \\ 0 \\ -0.1 \end{pmatrix},\quad \mathbf{W}^{(2)} = \begin{pmatrix} 0.5 & -1.0 & 0.2 \end{pmatrix},\quad b^{(2)} = 0.05 \]

Step 1 — apply Equation 2.1 for the hidden layer, using ReLU (Equation 1.5):

\[ \mathbf{z}^{(1)} = \mathbf{W}^{(1)}\mathbf{x}+\mathbf{b}^{(1)} = \begin{pmatrix} (0.4)(1)+(-0.2)(0.5)+0.1 \\ (0.1)(1)+(0.3)(0.5)+0 \\ (-0.5)(1)+(0.6)(0.5)-0.1 \end{pmatrix} = \begin{pmatrix} 0.4 \\ 0.25 \\ -0.3 \end{pmatrix} \;\;\Rightarrow\;\; \mathbf{a}^{(1)} = \text{ReLU}(\mathbf{z}^{(1)}) = \begin{pmatrix} 0.4 \\ 0.25 \\ 0 \end{pmatrix} \]

Step 2 — apply Equation 2.1 again for the output layer, using sigmoid (Equation 1.4):

\[ z^{(2)} = \mathbf{W}^{(2)}\mathbf{a}^{(1)}+b^{(2)} = (0.5)(0.4)+(-1.0)(0.25)+(0.2)(0)+0.05 = 0.0 \;\;\Rightarrow\;\; \hat{y} = \sigma(0) = 0.5 \]

Every step here was a direct application of Equations 1.1, 1.2/1.5, and 2.1 — there is no missing step. Note the third hidden neuron (\(a_3\)) computed a negative pre-activation (\(-0.3\)) and ReLU zeroed it out entirely; that neuron simply didn't "fire" for this particular input, which is exactly the kind of conditional, non-linear behaviour a single weighted sum could never produce on its own.

Chapter 03

How Networks Learn: Loss & Gradient Descent

Where the numbers in every weight matrix actually come from.

When a network is first created, every weight and bias is set to a small random number. Fed an input, it produces a more or less random output. Training is the repeated process of measuring how wrong that output is, and nudging every single weight and bias — sometimes billions of them — very slightly in the direction that makes it a little less wrong. Do this enough times, on enough examples, and the random numbers slowly settle into the values that let the network do something useful. This chapter covers the three ingredients of that process: the loss function (how wrong?), the gradient (which direction is "less wrong"?), and the optimizer (how big a step to take?).

The loss function: turning "wrong" into a number

A loss function compares the network's prediction \(\hat{\mathbf{y}}\) to the true answer \(\mathbf{y}\) and outputs a single number: 0 if the prediction was perfect, and larger the more wrong it was. The specific loss function used to train essentially every modern language model — including every model discussed in Chapter 10 — is cross-entropy loss, because the task is always the same underlying problem: "given the text so far, predict a probability for every possible next word (or word-piece)."

Equation 3.1 — Cross-entropy loss (the loss behind every LLM)
\[ L = -\sum_{i=1}^{V} y_i \log(\hat{y}_i) \]
What does each symbol mean?
\(V\)
The size of the vocabulary — the total number of possible tokens (word-pieces) the model can output. For modern LLMs this is commonly in the range of 100,000–250,000.
\(\hat{y}_i\)
The probability the model assigned to token \(i\) being the correct next token (a number between 0 and 1, and all \(\hat{y}_i\) values sum to 1 — this comes from the softmax function, Equation 6.2).
\(y_i\)
The "ground truth" — 1 for the token that actually came next in the real training text, and 0 for every other token in the vocabulary.
Why \(\log\)?
Because \(y_i\) is 1 for exactly one token and 0 for all others, the sum collapses to just \(-\log(\hat{y}_{\text{correct}})\). If the model assigned the correct token a probability near 1, \(\log\) is near 0 → tiny loss. If it assigned the correct token a probability near 0, \(\log\) shoots toward \(-\infty\) → huge loss. This is exactly the "punish confident wrong answers much more than uncertain ones" behaviour you want.

The gradient: which way is downhill?

Imagine the loss as a vast, hilly landscape, where the "location" is the entire set of weights and the "altitude" is the loss \(L\). Training a model is hiking down this landscape in fog, trying to reach the lowest point. The gradient of the loss with respect to a weight, written \(\frac{\partial L}{\partial w}\), tells you the slope of the ground right under that one weight's "dial" — if you turn the dial up slightly, does the loss go up or down, and how fast?

Equation 3.2 — Gradient descent update rule
\[ w \;\leftarrow\; w - \eta \,\frac{\partial L}{\partial w} \]
What does each symbol mean?
\(w\)
Any single weight (or bias) in the network — this update is applied to every parameter, separately, after every training step.
\(\leftarrow\)
"Gets replaced by" — the new value of \(w\) is the old value, minus a small adjustment.
\(\eta\)
The learning rate (eta) — a small positive number (e.g. 0.0001) chosen before training that controls the step size. Too large, and training overshoots and becomes unstable; too small, and training takes forever.
\(\frac{\partial L}{\partial w}\)
The gradient — how much the loss \(L\) would change for a tiny increase in \(w\). A positive gradient means increasing \(w\) increases the loss, so we subtract it (move \(w\) down); a negative gradient means the opposite, so subtracting a negative number increases \(w\).

Backpropagation: computing every gradient efficiently

A modern LLM has billions of weights spread across hundreds of layers. Computing \(\frac{\partial L}{\partial w}\) for every single one might sound impossibly slow — but there's an elegant shortcut called backpropagation, which is just a careful, systematic application of the chain rule from calculus: the gradient for a weight deep inside the network can be computed from the gradient of the layer just after it, multiplied by a local factor. This means gradients can be computed for an entire network in a single backward sweep, layer by layer, from the output back to the input.

Equation 3.3 — Backpropagation: the error signal at each layer
\[ \boldsymbol{\delta}^{(l)} = \left(\left(\mathbf{W}^{(l+1)}\right)^{\top}\boldsymbol{\delta}^{(l+1)}\right) \odot f'\!\left(\mathbf{z}^{(l)}\right) \]
What does each symbol mean?
\(\boldsymbol{\delta}^{(l)}\)
The "error signal" for layer \(l\) — one number per neuron in that layer, representing how much that neuron's pre-activation \(z\) contributed to the final loss.
\(\left(\mathbf{W}^{(l+1)}\right)^{\top}\)
The transpose (rows and columns swapped) of the next layer's weight matrix — this routes the error signal backward along the same connections it travelled forward on.
\(\boldsymbol{\delta}^{(l+1)}\)
The error signal already computed for the next layer — this is why the computation proceeds backward, from the output layer toward the input layer.
\(f'(\mathbf{z}^{(l)})\)
The derivative (instantaneous slope) of the activation function, evaluated at this layer's pre-activation values — it scales the error by how sensitive this neuron's output was to its input.
\(\odot\)
Element-by-element multiplication (Hadamard product): multiply each entry of the left vector by the corresponding entry of the right vector.
Equation 3.4 — Backpropagation: the gradient for each weight and bias
\[ \frac{\partial L}{\partial \mathbf{W}^{(l)}} = \boldsymbol{\delta}^{(l)} \left(\mathbf{a}^{(l-1)}\right)^{\top}, \qquad \frac{\partial L}{\partial \mathbf{b}^{(l)}} = \boldsymbol{\delta}^{(l)} \]
What does each symbol mean?
\(\boldsymbol{\delta}^{(l)}\left(\mathbf{a}^{(l-1)}\right)^{\top}\)
The outer product of this layer's error signal with the previous layer's activations — the result is a matrix the same shape as \(\mathbf{W}^{(l)}\), giving exactly one gradient value per weight, ready to be plugged into Equation 3.2.
\(\frac{\partial L}{\partial \mathbf{b}^{(l)}}\)
The bias gradients are simply the error signal itself — no multiplication needed, since a bias doesn't depend on the previous layer's activations.

Adam: the optimizer that actually trains every LLM in this report

In practice, no large model is trained with plain gradient descent (Equation 3.2). They use Adam (or its common variant AdamW) — an optimizer that keeps a running memory of recent gradients (momentum) and automatically adapts the step size for each individual weight. Every model named in Chapter 10 — DeepSeek, Llama, Qwen, Nemotron, and (based on their published research practices) GPT, Gemini, and Claude — is trained with this family of optimizer.

Equation 3.5 — Adam optimizer update (applied to every parameter, every step)
\[ \begin{aligned} \mathbf{m}_t &= \beta_1 \mathbf{m}_{t-1} + (1-\beta_1)\,\mathbf{g}_t \\ \mathbf{v}_t &= \beta_2 \mathbf{v}_{t-1} + (1-\beta_2)\,\mathbf{g}_t^2 \\ \hat{\mathbf{m}}_t &= \mathbf{m}_t / (1-\beta_1^t), \qquad \hat{\mathbf{v}}_t = \mathbf{v}_t / (1-\beta_2^t) \\ \boldsymbol{\theta}_t &= \boldsymbol{\theta}_{t-1} - \eta \cdot \frac{\hat{\mathbf{m}}_t}{\sqrt{\hat{\mathbf{v}}_t}+\epsilon} \end{aligned} \]
What does each symbol mean?
\(\boldsymbol{\theta}_t\)
The full set of parameters (every weight and bias, all stacked together) after training step \(t\) — this generalises the single weight \(w\) from Equation 3.2 to the whole model at once.
\(\mathbf{g}_t\)
The gradient of the loss with respect to \(\boldsymbol{\theta}\) at step \(t\), computed by backpropagation (Equations 3.3–3.4).
\(\mathbf{m}_t\)
The running average of past gradients ("momentum") — smooths out noisy, jittery gradients so training moves more steadily.
\(\mathbf{v}_t\)
The running average of past squared gradients — tracks how large recent gradients have typically been, so each parameter gets its own adaptive step size.
\(\beta_1,\beta_2\)
Decay rates controlling how much weight is given to the past vs. the present (commonly \(\beta_1=0.9\), \(\beta_2=0.999\)).
\(\hat{\mathbf{m}}_t, \hat{\mathbf{v}}_t\)
"Bias-corrected" versions of \(\mathbf{m}_t, \mathbf{v}_t\) — a small correction so the early training steps (when the running averages start at zero) aren't artificially too small.
\(\epsilon\)
A tiny constant (e.g. \(10^{-8}\)) to prevent division by zero.
\(\eta\)
The learning rate, same role as in Equation 3.2.
The training loop, end to end

Take a batch of text → run it forward through every equation in Chapters 1–2 (or, for a Transformer, Chapters 5–8) to get predictions → compute the loss with Equation 3.1 → run backpropagation (Equations 3.3–3.4) to get a gradient for every parameter → update every parameter with Adam (Equation 3.5) → repeat, often trillions of times, on trillions of words of text. The final values left in every \(\mathbf{W}\) and \(\mathbf{b}\) after this process finishes are "the weights" that get published (for open models) or kept private (for closed models) and used to answer your questions.

Chapter 04

Why Transformers? From RNNs to Attention

The architectural leap that made today's LLMs possible — and the map for the rest of this report.

The MLP from Chapter 2 takes a fixed-size input and produces a fixed-size output. But language is a sequence of variable length, where every word's meaning depends on words that came both before and after it. Before 2017, the standard approach was the Recurrent Neural Network (RNN) and its variant the LSTM — these read a sentence one word at a time, carrying a "memory" vector forward from each step to the next. This worked, but had two serious problems: it was inherently sequential (word 50 couldn't be processed until word 49 was done, making it slow on modern parallel hardware), and the memory vector tended to "forget" information from far earlier in long sequences.

In 2017, a paper titled "Attention Is All You Need" introduced the Transformer, which solved both problems with one idea: instead of passing information step-by-step through a memory vector, let every word look directly at every other word in the sequence, all at once, weighting how much attention to pay to each one. This mechanism — self-attention — is the single most important equation in this entire report, and Chapter 6 is dedicated to it.

Almost every model in Chapter 10 — GPT, Claude, Gemini, Llama, DeepSeek, Qwen, Nemotron — uses a decoder-only Transformer: a single stack of identical blocks that reads tokens from left to right and, at each position, predicts a probability distribution over what the next token should be (using the cross-entropy loss from Equation 3.1). Generating text means repeatedly: predict the next token, append it, feed the longer sequence back in, and predict again — this is called autoregressive generation. The maximum number of tokens the model can look at simultaneously is its context window — a number you'll see quoted for every model in Chapter 10 (e.g. "1 million tokens").

Chapter 05

Tokens, Embeddings & Position

Turning words into numbers — and giving those numbers a sense of order.

A neural network only understands numbers, so the first job of any Transformer is to turn text into numbers. This happens in two steps: tokenization chops the text into small pieces (often sub-words — "Transformers" might become "Transform" + "ers"), and each unique piece is assigned a fixed integer ID from a fixed-size vocabulary (the \(V\) from Equation 3.1). The model never sees the letters "c", "a", "t" — it sees a number, say, "4271".

The embedding matrix: the model's first weight table

A raw integer ID carries no useful information about meaning. So the very first learned component of every Transformer is an embedding matrix — a giant lookup table where row \(i\) is a vector of \(d_{\text{model}}\) numbers representing token \(i\). These numbers are weights, exactly like the weights in Chapter 2 — they start random and are trained by backpropagation, and by the end of training, tokens with similar meanings end up with similar vectors.

Equation 5.1 — The embedding lookup
\[ \mathbf{x} = \mathbf{E}[\text{id}, :] \in \mathbb{R}^{d_{\text{model}}} \]
What does each symbol mean?
\(\mathbf{E}\)
The embedding matrix, shape \(V \times d_{\text{model}}\) — \(V\) rows (one per vocabulary token) by \(d_{\text{model}}\) columns.
\(d_{\text{model}}\)
The "width" of the model — the size of the vector used to represent every token everywhere in the network. Common values range from a few hundred (tiny models) to over 7,000 (DeepSeek-V3, Chapter 10).
\(\text{id}\)
The integer index of the current token in the vocabulary.
\(\mathbf{E}[\text{id}, :]\)
"Row \(\text{id}\) of matrix \(\mathbf{E}\)" — simply selecting one entire row, which becomes the vector \(\mathbf{x}\) that flows into Figure 4.1.

Why position needs its own equation

Equation 6.1 (next chapter) treats the input as a set of vectors — without extra information, "the cat sat on the mat" and "the mat sat on the cat" would look identical to the attention mechanism, because it has no built-in notion of order. Every Transformer therefore adds a positional encoding that injects "this is token number 0 / 1 / 2 / …" into the calculation. Two schemes matter for this report.

Equation 5.2 — Sinusoidal positional encoding (the original 2017 scheme)
\[ PE_{(pos,\,2i)} = \sin\!\left(\frac{pos}{10000^{\,2i/d_{\text{model}}}}\right), \qquad PE_{(pos,\,2i+1)} = \cos\!\left(\frac{pos}{10000^{\,2i/d_{\text{model}}}}\right) \]
What does each symbol mean?
\(pos\)
The position of the token in the sequence: 0 for the first token, 1 for the second, and so on.
\(i\)
An index over pairs of dimensions in the embedding (so \(2i\) and \(2i{+}1\) are an even/odd pair of coordinates).
\(10000\)
A fixed constant ("base") chosen so that different dimensions oscillate at very different frequencies — some change quickly from token to token, others change very slowly across the whole sequence.
Result
A vector \(\mathbf{PE}_{pos}\) of the same size as the token embedding, which is simply added to it: \(\mathbf{x}' = \mathbf{x} + \mathbf{PE}_{pos}\), before the result enters the first Transformer block.
Equation 5.3 — RoPE: Rotary Position Embedding (used by virtually every model in Chapter 10)
\[ R(m\theta_j) = \begin{pmatrix} \cos(m\theta_j) & -\sin(m\theta_j) \\ \sin(m\theta_j) & \cos(m\theta_j) \end{pmatrix}, \qquad \theta_j = \text{base}^{-2j/d} \]
What does each symbol mean?
\(m\)
The position of the token (same role as \(pos\) above).
\(j\)
Which 2-dimensional pair of coordinates within the query/key vector this rotation applies to (the full vector is split into \(d/2\) such pairs, each with its own \(\theta_j\)).
\(\theta_j\)
The rotation "speed" for pair \(j\) — \(\text{base}\) is a large constant (commonly 10,000, just like Equation 5.2). Low-\(j\) pairs rotate quickly per position; high-\(j\) pairs rotate very slowly.
\(R(m\theta_j)\)
A standard 2D rotation matrix — multiplying a 2D vector by this matrix simply spins it by the angle \(m\theta_j\), without changing its length.
How it's used
Unlike Equation 5.2, RoPE is not added to the embedding. Instead, right before the attention calculation in Chapter 6, every Query and Key vector is rotated by an angle proportional to its position. Two tokens 5 positions apart end up with a relative rotation of exactly \(5\theta_j\) between their Query and Key — so the attention score in Equation 6.1 naturally depends on how far apart two tokens are, not just their raw content.
Chapter 06

Self-Attention: the Heart of the Transformer

The equation that lets every word look directly at every other word.

Queries, Keys, and Values

For every token, the Transformer computes three different vectors from its current representation \(\mathbf{x}\), using three more learned weight matrices:

Equation 6.0 — Query, Key, and Value projections
\[ \mathbf{Q} = \mathbf{X}\mathbf{W}_Q, \qquad \mathbf{K} = \mathbf{X}\mathbf{W}_K, \qquad \mathbf{V} = \mathbf{X}\mathbf{W}_V \]
What does each symbol mean?
\(\mathbf{X}\)
A matrix stacking the (position-aware) vectors for every token in the sequence — one row per token.
\(\mathbf{W}_Q,\mathbf{W}_K,\mathbf{W}_V\)
Three separate learned weight matrices — exactly like \(\mathbf{W}^{(l)}\) from Chapter 2, just with new names. These are the parameters that get trained so that "Query," "Key," and "Value" each capture something useful.
\(\mathbf{Q}\) (Query)
"What is this token looking for?" — think of it as the question each token asks of the rest of the sequence.
\(\mathbf{K}\) (Key)
"What does this token have to offer?" — a label that other tokens' queries are compared against.
\(\mathbf{V}\) (Value)
"What information does this token actually contain?" — the content that gets passed along if it's deemed relevant.

Scaled dot-product attention

Attention works by comparing every token's Query against every token's Key. A high similarity (a large dot product) means "this token is relevant to me" — and the more relevant a token is, the more of its Value gets mixed into the output.

Equation 6.1 — Scaled dot-product (self-)attention
\[ \text{Attention}(\mathbf{Q},\mathbf{K},\mathbf{V}) = \text{softmax}\!\left(\frac{\mathbf{Q}\mathbf{K}^{\top}}{\sqrt{d_k}}\right)\mathbf{V} \]
What does each symbol mean?
\(\mathbf{Q}\mathbf{K}^{\top}\)
A matrix of raw similarity scores — entry \((i,j)\) is the dot product of token \(i\)'s Query with token \(j\)'s Key: "how much does token \(i\) care about token \(j\)?"
\(d_k\)
The dimensionality of each Query/Key vector. Dividing by \(\sqrt{d_k}\) keeps the scores from growing too large as \(d_k\) increases, which keeps training stable (this is the entire reason for the word "scaled" in the name).
\(\text{softmax}\)
Defined in Equation 6.2 below — turns each row of raw scores into a set of positive numbers that sum to 1, i.e. a probability distribution over "which other tokens to pay attention to."
\(\mathbf{V}\)
The Value matrix from Equation 6.0.
Result
For each token, a new vector that is a weighted average of every token's Value vector — weighted by how much attention that token decided to pay to each other token.
Equation 6.2 — Softmax
\[ \text{softmax}(\mathbf{z})_i = \frac{e^{z_i}}{\sum_{j} e^{z_j}} \]
What does each symbol mean?
\(\mathbf{z}\)
Any vector of raw numbers (here, one row of attention scores; in Equation 3.1, the model's final output scores over the vocabulary).
\(e^{z_i}\)
Exponentiating makes every value positive, and amplifies differences — a slightly larger score becomes a much larger exponentiated value.
\(\sum_j e^{z_j}\)
The sum of all exponentiated values — dividing by this total ensures every output is between 0 and 1 and the whole row sums to exactly 1, i.e. a valid probability distribution.

A tiny worked example: attention with two tokens

Suppose, after Equation 6.0, token 1 has produced the query \(\mathbf{q}_1=(1,0)\), and the two tokens have keys \(\mathbf{k}_1=(1,0)\), \(\mathbf{k}_2=(0,1)\) and values \(\mathbf{v}_1=(1,2)\), \(\mathbf{v}_2=(3,4)\), with \(d_k=2\) so \(\sqrt{d_k}\approx1.414\). Let's compute token 1's new representation:

Step 1 — raw scores (\(\mathbf{q}_1\cdot\mathbf{k}_j\)), then scale by \(\sqrt{d_k}\):

\[ \frac{\mathbf{q}_1\cdot\mathbf{k}_1}{\sqrt{d_k}} = \frac{(1)(1)+(0)(0)}{1.414} \approx 0.707, \qquad \frac{\mathbf{q}_1\cdot\mathbf{k}_2}{\sqrt{d_k}} = \frac{(1)(0)+(0)(1)}{1.414} = 0 \]

Step 2 — apply softmax (Equation 6.2) to \((0.707,\ 0)\):

\[ \text{softmax}(0.707,\ 0) = \left(\frac{e^{0.707}}{e^{0.707}+e^{0}},\ \frac{e^{0}}{e^{0.707}+e^{0}}\right) \approx (0.670,\ 0.330) \]

Step 3 — use these as weights to blend the Value vectors:

\[ \text{output}_1 = 0.670\,\mathbf{v}_1 + 0.330\,\mathbf{v}_2 = 0.670(1,2)+0.330(3,4) \approx (1.66,\ 2.66) \]

Token 1 ended up paying about 67% attention to itself and 33% to token 2, and its new vector is exactly that weighted blend of their Value vectors. Scale this same calculation up to thousands of tokens and hundreds of dimensions, and you have the core operation that every Transformer in this report performs, over and over, at every layer.

Multi-head attention: running this several times in parallel

A single attention calculation can only learn one "kind" of relationship at a time. So every Transformer layer instead runs several smaller attention calculations side-by-side — called heads — each with its own \(\mathbf{W}_Q,\mathbf{W}_K,\mathbf{W}_V\), free to specialise (one head might learn to track grammatical subjects, another might track "which pronoun refers to which noun"). Their outputs are then stitched back together.

Equation 6.3 — Multi-head attention
\[ \text{MultiHead}(\mathbf{Q},\mathbf{K},\mathbf{V}) = \text{Concat}(\text{head}_1,\dots,\text{head}_h)\,\mathbf{W}^{O}, \qquad \text{head}_i = \text{Attention}(\mathbf{Q}\mathbf{W}_i^{Q},\,\mathbf{K}\mathbf{W}_i^{K},\,\mathbf{V}\mathbf{W}_i^{V}) \]
What does each symbol mean?
\(h\)
The number of attention heads — a fixed design choice (Chapter 10 lists the actual value for each model, e.g. 128 for DeepSeek-V3).
\(\mathbf{W}_i^{Q},\mathbf{W}_i^{K},\mathbf{W}_i^{V}\)
Each head's own, smaller projection matrices — applied to the shared \(\mathbf{Q},\mathbf{K},\mathbf{V}\) from Equation 6.0 to give that head its own "view." Typically each head works in a smaller dimension \(d_k = d_{\text{model}}/h\), so the total compute stays roughly the same as one big head.
\(\text{head}_i\)
The output of Equation 6.1, computed independently for head \(i\).
\(\text{Concat}(\cdot)\)
Stick all \(h\) heads' output vectors side-by-side into one long vector, back to size \(d_{\text{model}}\).
\(\mathbf{W}^{O}\)
One final learned weight matrix that mixes the concatenated heads back into a single combined output — the result that flows into the "Add & Norm" step of Figure 4.1.
One more detail: causal masking

Because decoder-only models (Chapter 4) predict the next token, a token must never be allowed to "peek" at tokens that come after it — that would be cheating. Before the softmax in Equation 6.1, every score \((\mathbf{Q}\mathbf{K}^{\top})_{ij}\) where \(j>i\) (a future token) is set to \(-\infty\). Since \(e^{-\infty}=0\), softmax assigns these positions exactly zero attention — token \(i\) can only attend to itself and tokens before it. This is called a causal mask.

Chapter 07

Normalization, Residuals & the Feed-Forward Block

The "plumbing" that lets a Transformer be hundreds of layers deep without breaking.

Residual connections: a shortcut around every sub-layer

Stacking dozens or hundreds of layers (Figure 4.1's "×N") creates a practical problem: during backpropagation (Equation 3.3), the error signal has to travel back through every single layer, and it can shrink to almost nothing by the time it reaches the early layers — a problem known as vanishing gradients. The fix is strikingly simple: add the input of a sub-layer directly to its output, creating a "shortcut" that gradients can flow through unimpeded.

Equation 7.1 — Residual (skip) connection
\[ \mathbf{h}' = \mathbf{h} + \text{Sublayer}(\mathbf{h}) \]
What does each symbol mean?
\(\mathbf{h}\)
The vector(s) entering a sub-layer (either the Multi-Head Attention block or the Feed-Forward block from Figure 4.1).
\(\text{Sublayer}(\cdot)\)
Whatever that block computes — Equation 6.3 for attention, or Equation 7.4 below for the feed-forward network.
\(\mathbf{h}'\)
The output — the original input, plus whatever the sub-layer "decided to change." Early in training, when the sub-layer's output is near zero, \(\mathbf{h}'\approx\mathbf{h}\) — information passes through unchanged by default, and the network only has to learn useful modifications.

Normalization: keeping numbers in a healthy range

As vectors flow through dozens of layers, their values can drift to extreme magnitudes, destabilising training. Normalization rescales a vector back to a consistent range before it's used. The original 2017 Transformer used LayerNorm; almost every model in Chapter 10 (Llama, DeepSeek, Qwen, Nemotron, and — per their public architecture descriptions — Gemini) instead uses the simpler, cheaper RMSNorm.

Equation 7.2 — Layer Normalization (LayerNorm)
\[ \text{LayerNorm}(\mathbf{x}) = \frac{\mathbf{x}-\mu}{\sqrt{\sigma^2+\epsilon}} \odot \boldsymbol{\gamma} + \boldsymbol{\beta} \]
What does each symbol mean?
\(\mu, \sigma^2\)
The mean and variance of all the numbers within a single vector \(\mathbf{x}\) (e.g., across all \(d_{\text{model}}\) entries for one token) — computed fresh for every token, every layer.
\(\frac{\mathbf{x}-\mu}{\sqrt{\sigma^2+\epsilon}}\)
Subtract the mean and divide by the standard deviation — the classic "standardisation" formula, giving a vector with mean 0 and variance 1.
\(\boldsymbol{\gamma}, \boldsymbol{\beta}\)
Two more learned weight vectors (a rescale and a shift) — these let the network "undo" the standardisation if that turns out to be useful, while still keeping training stable.
\(\epsilon\)
A tiny constant preventing division by zero, same role as in Equation 3.5.
Equation 7.3 — RMSNorm (Root Mean Square Normalization)
\[ \text{RMSNorm}(\mathbf{x}) = \frac{\mathbf{x}}{\sqrt{\dfrac{1}{d}\sum_{i=1}^{d} x_i^2 + \epsilon}} \odot \boldsymbol{\gamma} \]
What does each symbol mean?
\(\sqrt{\dfrac{1}{d}\sum_i x_i^2}\)
The root mean square of the vector's entries — a measure of its overall size, without first centring it (no mean-subtraction step).
\(d\)
The number of entries in \(\mathbf{x}\) (e.g. \(d_{\text{model}}\)).
\(\boldsymbol{\gamma}\)
A learned rescaling vector (RMSNorm drops LayerNorm's \(\boldsymbol{\beta}\) shift entirely).
Why bother changing it?
RMSNorm removes the mean-and-variance computation, needing fewer operations per token. Across a model with hundreds of layers and trillions of training tokens, this adds up to a meaningful reduction in training cost with little to no quality loss — which is why it became the default.

Pre-norm: where exactly does normalization go?

The original Transformer normalized after adding the residual ("post-norm"): \(\text{LayerNorm}(\mathbf{h}+\text{Sublayer}(\mathbf{h}))\). Virtually every model in Chapter 10 instead uses pre-norm — normalizing the input to the sub-layer, while keeping the residual connection itself completely "clean":

Equation 7.4 — Pre-norm residual block (the modern standard)
\[ \mathbf{h}' = \mathbf{h} + \text{Sublayer}\big(\text{RMSNorm}(\mathbf{h})\big) \]
What does each symbol mean?
Why this ordering?
The residual "shortcut" (Equation 7.1) carries \(\mathbf{h}\) forward completely untouched — normalization only affects the copy that goes into the sub-layer. This keeps the gradient shortcut as direct as possible, which in practice makes very deep stacks (Figure 4.1's "×N", where N can exceed 60) much easier to train without the loss spiking or diverging.

The feed-forward network: where most of a model's "memory" lives

After attention lets tokens exchange information, each token is processed independently by a small two-layer MLP (exactly the structure from Chapter 2!) that expands its vector to a larger size, applies a non-linearity, and projects it back down. The original Transformer used a plain ReLU MLP:

Equation 7.5 — Original feed-forward network (ReLU)
\[ \text{FFN}(\mathbf{x}) = \max(0,\ \mathbf{x}\mathbf{W}_1+\mathbf{b}_1)\,\mathbf{W}_2+\mathbf{b}_2 \]
What does each symbol mean?
\(\mathbf{W}_1\)
Expands \(\mathbf{x}\) from \(d_{\text{model}}\) up to a larger "inner" dimension \(d_{ff}\) (commonly \(d_{ff}=4\times d_{\text{model}}\)).
\(\max(0,\cdot)\)
ReLU (Equation 1.5), applied element-wise.
\(\mathbf{W}_2\)
Projects back down from \(d_{ff}\) to \(d_{\text{model}}\), so the result can be added back via Equation 7.1.

Every modern model in Chapter 10 instead uses a gated variant built from SiLU (Equation 1.6), called SwiGLU:

Equation 7.6 — SwiGLU feed-forward network (Llama, DeepSeek, Qwen, Nemotron, and more)
\[ \text{FFN}_{\text{SwiGLU}}(\mathbf{x}) = \Big(\text{SiLU}(\mathbf{x}\mathbf{W}_1) \odot (\mathbf{x}\mathbf{W}_3)\Big)\mathbf{W}_2 \]
What does each symbol mean?
\(\mathbf{W}_1, \mathbf{W}_3\)
Two separate learned matrices, each projecting \(\mathbf{x}\) from \(d_{\text{model}}\) up to \(d_{ff}\) — twice as many "expansion" weights as Equation 7.5.
\(\text{SiLU}(\mathbf{x}\mathbf{W}_1)\)
The "gate" — for every one of the \(d_{ff}\) values, this produces a number that controls how much of the corresponding value from \(\mathbf{x}\mathbf{W}_3\) is allowed through.
\(\odot\)
Element-wise multiplication (as in Equation 3.3) — the gate and the value streams are combined position-by-position.
\(\mathbf{W}_2\)
Projects the gated result back down from \(d_{ff}\) to \(d_{\text{model}}\), same role as in Equation 7.5.
Intuition
Think of \(\mathbf{x}\mathbf{W}_3\) as "candidate information" and \(\text{SiLU}(\mathbf{x}\mathbf{W}_1)\) as a learned "volume knob" deciding, value-by-value, how much of that candidate information should actually pass through — a more expressive, smoothly-trainable version of ReLU's all-or-nothing cutoff.
Chapter 08

The Full Transformer Block & How Weights Are Trained

Assembling every equation so far into one model — and the three-stage process that fills in every number.

The complete Transformer block, in two equations

Combine Equation 7.4 (pre-norm residual) with Equation 6.3 (attention) and Equation 7.6 (feed-forward), and one full "layer" of every model in Chapter 10 is exactly these two lines:

Equation 8.1 — One complete Transformer block
\[ \begin{aligned} \mathbf{h}' &= \mathbf{h} + \text{MultiHead}\big(\text{RMSNorm}(\mathbf{h})\big) \\ \mathbf{h}'' &= \mathbf{h}' + \text{FFN}_{\text{SwiGLU}}\big(\text{RMSNorm}(\mathbf{h}')\big) \end{aligned} \]
What does each symbol mean?
\(\mathbf{h}\)
The input to this layer — for the very first layer, this is the token embeddings plus positional information from Chapter 5; for every later layer, it's \(\mathbf{h}''\) from the layer before.
Line 1
The attention sub-block from Figure 4.1: normalize, run multi-head self-attention (Equation 6.3, with RoPE applied inside it per Equation 5.3, and the causal mask applied), add back the residual.
Line 2
The feed-forward sub-block from Figure 4.1: normalize the result of line 1, run it through the SwiGLU MLP (Equation 7.6), add back the residual.
\(\mathbf{h}''\)
The output of this layer, which becomes \(\mathbf{h}\) for the next layer. Repeat this block \(N\) times (Figure 4.1's "×N") — \(N\) is the model's number of layers, a number you'll see for every model in Chapter 10.

From the last layer to a prediction

After the final (\(N\)-th) block, one more normalization is applied, and the resulting vector for each token is multiplied by an unembedding matrix to produce one raw score per vocabulary word — which softmax (Equation 6.2) turns into the probability distribution that Equation 3.1's loss compares against the true next word during training.

Equation 8.2 — Final prediction (next-token probabilities)
\[ P(\text{token} = i \mid \text{context}) = \text{softmax}\big(\text{RMSNorm}(\mathbf{h}^{(N)})\,\mathbf{W}_U\big)_i \]
What does each symbol mean?
\(\mathbf{h}^{(N)}\)
The output of the final (\(N\)-th) Transformer block (Equation 8.1) for the current token position.
\(\mathbf{W}_U\)
The unembedding matrix, shape \(d_{\text{model}}\times V\) — projects from model-width back to one score per vocabulary token. Many models save parameters by reusing ("tying") this with the embedding matrix \(\mathbf{E}\) from Equation 5.1, i.e. \(\mathbf{W}_U = \mathbf{E}^{\top}\).
\(P(\text{token}=i\mid\text{context})\)
The final output: a probability, between 0 and 1, that vocabulary token \(i\) is the correct next token — exactly the \(\hat{y}_i\) from Equation 3.1.
Putting it all together: one sentence through the whole model

Text → tokens → Equation 5.1 (embedding lookup) → Equations 5.2/5.3 (add position) → Equation 8.1, repeated \(N\) times (each repeat: attention lets tokens exchange information, then the feed-forward network processes each token individually, both wrapped in residual+norm) → Equation 8.2 (final probability over the next token). Every arrow in Figure 4.1 is now backed by a numbered equation.

How every number gets filled in: the three-stage training pipeline

Chapter 03 explained the mechanism (gradient descent + backpropagation + Adam) that adjusts weights. In practice, training a model like the ones in Chapter 10 happens in three distinct stages, each using that same mechanism on different data:

Stage 1 — Pretraining is by far the most expensive stage, and is where the overwhelming majority of a model's factual knowledge and language ability comes from: the raw Equation 8.1/8.2 pipeline is run on a huge, broad corpus of text (web pages, books, code, and more — for the open models in Chapter 10, this is measured in the tens of trillions of tokens), minimizing Equation 3.1's cross-entropy loss at every position in every document simultaneously. Stage 2 — Supervised Fine-Tuning (SFT) continues training, but now on a smaller, carefully curated set of example conversations/instructions and ideal responses — this is what turns a model that merely "continues text" into one that recognisably answers questions and follows instructions. Stage 3 — RLHF / RLAIF (Reinforcement Learning from Human, or AI, Feedback) further adjusts the weights using a reward signal — a separate model trained to score how good a response is — to push the model's outputs toward being more helpful, honest, and safe. Anthropic's Claude family uses a specific published variant called Constitutional AI (CAI): before human raters score responses, an AI critic iteratively critiques and revises the model's own outputs against a written "constitution" of principles (harmlessness, honesty, and so on). This AI-feedback loop is what makes it RLAIF specifically — reducing the human annotation burden while encoding explicit values into the reward signal itself. The PPO or DPO update then fine-tunes the weights toward responses the reward model prefers. The numbers left in every \(\mathbf{W}\) after all three stages are "the weights" referred to throughout Chapter 10.

Chapter 09

Scaling Tricks Behind Today's Giants

Five modifications to Chapters 06–08 that let models grow to hundreds of billions of weights without becoming impossibly slow.

Everything so far describes a "vanilla" Transformer. To reach the scale of the models in Chapter 10, every one of them modifies at least one of Equations 6.3, 7.6, or 8.1 in one of the following five ways. Each is a genuine equation in active use today — not a simplification.

1. Mixture of Experts (MoE): many small FFNs instead of one giant one

Equation 7.6's feed-forward network is, by parameter count, the largest part of a Transformer block. Mixture of Experts replaces the single FFN with \(N_e\) separate "expert" FFNs (each its own complete SwiGLU from Equation 7.6, with its own \(\mathbf{W}_1,\mathbf{W}_2,\mathbf{W}_3\)), plus a small router network that looks at each token and decides which few experts should process it.

Equation 9.1 — Mixture-of-Experts layer
\[ \mathbf{y} = \sum_{i \,\in\, \text{TopK}(\mathbf{g}(\mathbf{x}))} g_i(\mathbf{x}) \cdot E_i(\mathbf{x}), \qquad \mathbf{g}(\mathbf{x}) = \text{softmax}(\mathbf{x}\mathbf{W}_{\text{router}}) \]
What does each symbol mean?
\(E_i(\mathbf{x})\)
The \(i\)-th expert — a complete FFN (Equation 7.6) with its own weights, applied to token \(\mathbf{x}\).
\(\mathbf{W}_{\text{router}}\)
A small learned weight matrix, shape \(d_{\text{model}}\times N_e\), producing one score per expert.
\(\mathbf{g}(\mathbf{x})\)
Softmax (Equation 6.2) over the router's scores — a probability-like weight for every expert.
\(\text{TopK}(\cdot)\)
Keep only the \(k\) experts with the highest \(g_i(\mathbf{x})\) (commonly \(k\) is somewhere between 1 and 10) — every other expert does zero work for this token.
\(\mathbf{y}\)
A weighted sum of just those \(k\) experts' outputs — this is what flows into Equation 8.1's second line.

This is the single most important idea behind the "total vs. active parameters" numbers you'll see throughout Chapter 10. Total parameters = every weight in every expert, added up (this is the number that determines file size on disk). Active parameters = only the weights actually used to process one token — the \(k\) selected experts (plus any "shared experts" that are always active for every token, used by several models in Chapter 10) and the rest of the model (attention, embeddings, etc.). A model can be enormous on disk while being relatively cheap to run, because most of it sits idle for any given token.

2. Grouped-Query Attention (GQA): cheaper memory during generation

During autoregressive generation (Chapter 04), a model must keep every previous token's Key and Value vectors (Equation 6.0) in memory — the KV cache — so it doesn't have to recompute them. With \(h\) attention heads, that's \(h\) separate K and V vectors per token, which becomes enormous for long contexts. Grouped-Query Attention keeps all \(h\) Query heads, but has groups of Query heads share a single Key/Value head.

Equation 9.2 — Grouped-Query Attention
\[ \text{head}_i = \text{Attention}\big(\mathbf{Q}\mathbf{W}_i^{Q},\ \mathbf{K}\mathbf{W}^{K}_{g(i)},\ \mathbf{V}\mathbf{W}^{V}_{g(i)}\big), \qquad g(i) = \left\lceil \frac{i \cdot G}{h} \right\rceil \]
What does each symbol mean?
\(h\)
The total number of Query heads (same as in Equation 6.3).
\(G\)
The number of Key/Value groups, where \(G \le h\). If \(G=h\), this is standard Multi-Head Attention (each head has its own K,V). If \(G=1\), every head shares one K,V (called Multi-Query Attention). GQA picks a value in between.
\(g(i)\)
A function mapping Query head \(i\) to one of the \(G\) shared K/V groups — every Query head in the same group reuses the exact same \(\mathbf{K}\mathbf{W}^K_{g(i)}\) and \(\mathbf{V}\mathbf{W}^V_{g(i)}\).
Effect
The KV cache shrinks by a factor of \(h/G\) compared to standard Multi-Head Attention, with a much smaller quality cost than going all the way to \(G=1\).

3. Multi-head Latent Attention (MLA): DeepSeek's KV cache compression

DeepSeek's models (Chapter 10) go further than GQA: instead of caching full-size K and V vectors for any heads at all, they compress the information needed to reconstruct K and V into one small shared vector per token — a latent — and cache only that.

Equation 9.3 — MLA: compress, then reconstruct
\[ \mathbf{c}_t^{KV} = \mathbf{W}^{DKV}\mathbf{h}_t, \qquad \mathbf{k}_t^{C} = \mathbf{W}^{UK}\mathbf{c}_t^{KV}, \qquad \mathbf{v}_t^{C} = \mathbf{W}^{UV}\mathbf{c}_t^{KV} \]
What does each symbol mean?
\(\mathbf{h}_t\)
The model's hidden vector for token \(t\) (size \(d_{\text{model}}\), e.g. 7168 for DeepSeek-V3).
\(\mathbf{W}^{DKV}\)
A "down-projection" matrix that compresses \(\mathbf{h}_t\) into a much smaller latent vector \(\mathbf{c}_t^{KV}\) (size \(d_c\), e.g. 512 — roughly 14× smaller than \(d_{\text{model}}\)). Only \(\mathbf{c}_t^{KV}\) is stored in the KV cache, not the full K/V.
\(\mathbf{W}^{UK}, \mathbf{W}^{UV}\)
"Up-projection" matrices that, whenever K or V are actually needed for Equation 6.1, reconstruct them on-the-fly from the cached latent \(\mathbf{c}_t^{KV}\), expanded back out across all \(h\) attention heads.

Because RoPE (Equation 5.3) depends on absolute position and doesn't play well with this compress/reconstruct trick, DeepSeek's models add one more small piece: a separate, uncompressed, low-dimensional slice of the Query and Key (dimension \(d_h^R\), e.g. 64) that does carry RoPE directly, concatenated onto the reconstructed \(\mathbf{k}_t^C\). This is referred to as "decoupled RoPE" — the bulk of each Key vector is reconstructed from the tiny cached latent, while a small dedicated slice handles position.

4. DeepSeek Sparse Attention (DSA): not every token needs to look at every other token

Equation 6.1's cost grows with the square of the sequence length — every token compares against every other token. For very long contexts, DeepSeek-V3.2 introduces a lightweight lightning indexer that first scores how relevant every earlier token is, then runs full attention only against the most relevant subset.

Equation 9.4 — Lightning indexer relevance score
\[ I_{t,s} = \sum_{j=1}^{H^{I}} w_{t,j}^{I} \cdot \text{ReLU}\big(\mathbf{q}_{t,j}^{I} \cdot \mathbf{k}_{s}^{I}\big) \]
What does each symbol mean?
\(I_{t,s}\)
The computed "relevance" of an earlier token \(s\) to the current token \(t\).
\(H^{I}\)
The number of small, separate "indexer heads" (distinct from the main attention heads).
\(\mathbf{q}_{t,j}^{I}, \mathbf{k}_{s}^{I}\)
Small query/key vectors produced specifically for the indexer (cheaper to compute than the full Equation 6.0 projections).
\(w_{t,j}^{I}\)
A learned per-head weighting for combining the indexer heads.
\(\text{ReLU}(\cdot)\)
Equation 1.5 — ensures only positively-relevant matches contribute.
How it's used
For each token \(t\), only the earlier tokens \(s\) with the highest \(I_{t,s}\) (e.g. the top few thousand, regardless of total context length) are passed into the full Equation 6.1 attention — letting the model support extremely long contexts without the quadratic blow-up.

5. Hybrid linear attention: mixing in recurrent-style layers

A final family of techniques — used by linear RNN variants (like Gated DeltaNet) and hybrid state-space models (such as those built on the Mamba-2 architecture) — takes a different approach: instead of every layer using Equation 6.1, most layers are replaced with a linear-cost recurrent layer that maintains a fixed-size "state" updated one token at a time (much like the RNNs from Chapter 04, but redesigned to be trainable in parallel and far more expressive). A smaller number of full attention layers are kept and interleaved throughout the stack to preserve the ability to look arbitrarily far back when needed.

Equation 9.5 — The general recurrence behind this layer family (the "delta rule")
\[ \mathbf{S}_t = \alpha_t\,\mathbf{S}_{t-1} + \beta_t\left(\mathbf{v}_t - \mathbf{S}_{t-1}\mathbf{k}_t\right)\mathbf{k}_t^{\top} \]
What does each symbol mean?
\(\mathbf{S}_t\)
A matrix-valued "state" — a compact, fixed-size memory carried from token to token (its size does not grow with sequence length, unlike the KV cache in Equation 9.2/9.3).
\(\mathbf{S}_{t-1}\mathbf{k}_t\)
"What the current memory would predict the value to be, given this token's key" — the gap between this prediction and the real value \(\mathbf{v}_t\) is the new information.
\(\beta_t\)
A learned, input-dependent "write strength" — how much of the new information to blend in.
\(\alpha_t\)
A learned, input-dependent "forget gate" — how much of the old state to retain (this is the "Gated" in Gated DeltaNet).

This is presented here as the general family of recurrence that this class of layers is built on, rather than the literal layer-by-layer specification of any single model — the exact configuration (which layers are linear vs. full-attention, exact state sizes, etc.) is part of each model's published architecture, discussed for modern architectures in Chapter 10.

Chapter 09 summary: which models use what

MoE (Equation 9.1) is used by DeepSeek-V3, Mixtral, and Gemini. GQA (Equation 9.2) is used by Llama 3/3.1/3.3 and DeepSeek. MLA (Equation 9.3) is DeepSeek-specific. Hybrid linear attention (Equation 9.5's family) is used by modern recurrent and state-space architectures like Mamba-2 and hybrid models. Chapter 10 maps every one of these onto real, published numbers.

Chapter 11

Glossary

Every key term from this report, in one place.

Activation function
A fixed, non-linear function (sigmoid, ReLU, SiLU, …) applied to a neuron's weighted sum to produce its output. See Equations 1.2–1.6.
Active parameters
In a Mixture-of-Experts model, the subset of total parameters actually used to process one token. See Equation 9.1.
Adam / AdamW
The optimizer used to train virtually every model in this report; adapts each weight's step size using running averages of gradients. See Equation 3.5.
Attention (self-attention)
The mechanism letting every token directly compare itself to, and draw information from, every other token. See Equation 6.1.
Autoregressive
Generating text one token at a time, feeding each new token back in to predict the next.
Backpropagation
The chain-rule algorithm that computes the gradient of the loss with respect to every weight in one backward pass. See Equations 3.3–3.4.
Bias
A learned per-neuron offset added to the weighted sum, independent of the inputs. See Equation 1.1.
Causal mask
Forces each token's attention to ignore all future tokens, so the model can't "see" the answer it's trying to predict.
Constitutional AI (CAI)
Anthropic's published variant of RLAIF (Stage 3 of Figure 8.1): an AI critic iteratively evaluates and revises a model's outputs against a written "constitution" of principles before human raters score them, reducing annotation cost while encoding explicit values into the reward signal. Used across all Claude models as the RLAIF branch of their training pipeline. See Bai et al., "Constitutional AI: Harmlessness from AI Feedback," 2022.
Context window
The maximum number of tokens a model can process at once.
Cross-entropy loss
The standard loss function for next-token prediction; heavily penalizes confident wrong predictions. See Equation 3.1.
Decoder-only
A Transformer consisting of a single stack of blocks that predicts the next token, used by essentially every model in Chapter 10.
DeepSeek Sparse Attention (DSA)
DeepSeek's technique for selecting only the most relevant earlier tokens before running full attention. See Equation 9.4.
Embedding (matrix)
A learned lookup table converting token IDs into vectors. See Equation 5.1.
Epoch / training step
One pass of forward computation, loss measurement, and weight update across a batch of data.
Feed-forward network (FFN)
A small two-layer MLP applied to each token independently inside a Transformer block. See Equations 7.5–7.6.
Gradient
How much the loss would change for a tiny change in one parameter — the "slope" used by gradient descent. See Equation 3.2.
Gated DeltaNet
A linear-cost recurrent attention alternative built on the "delta rule." See Equation 9.5.
Grouped-Query Attention (GQA)
Multiple Query heads share a single Key/Value head, shrinking the KV cache. See Equation 9.2.
Hidden layer
Any layer of neurons between the input and output layers of a network.
KV cache
The stored Key and Value vectors for all previous tokens, kept in memory during text generation so they aren't recomputed.
Layer (Transformer block)
One repetition of attention + feed-forward (Equation 8.1); large models stack dozens to ~60+ of these.
LayerNorm
Normalizes a vector to zero mean and unit variance, then rescales/shifts with learned parameters. See Equation 7.2.
Learning rate (η)
The step size used when updating weights during training. See Equation 3.2.
Logit
A raw, pre-activation or pre-softmax score — see "pre-activation" (Equation 1.1) and the final output of Equation 8.2 before softmax.
Mixture of Experts (MoE)
Replacing one feed-forward network with many "expert" networks, of which only a few run per token, selected by a router. See Equation 9.1.
Multi-head Latent Attention (MLA)
DeepSeek's technique for compressing Key/Value information into a small cached "latent" vector. See Equation 9.3.
Multi-head attention
Running several attention calculations in parallel, each able to specialise in different relationships. See Equation 6.3.
Multi-Layer Perceptron (MLP)
A network of fully-connected layers, each computing Equation 2.1.
Neuron
The basic unit: a weighted sum of inputs plus a bias, passed through an activation function. See Equations 1.1–1.2.
Parameters
Every weight and bias in a model, collectively — the numbers that training adjusts.
Positional encoding
Information injected into a Transformer so it knows the order of tokens. See Equations 5.2 (sinusoidal) and 5.3 (RoPE).
Pre-norm
Applying normalization to the input of a sub-layer (rather than its output) before adding the residual. See Equation 7.4.
Query / Key / Value (Q/K/V)
Three vectors computed per token for attention: "what I'm looking for," "what I offer," and "what I actually contain." See Equation 6.0.
ReLU
"Rectified Linear Unit" — outputs zero for negative inputs and passes positive inputs through unchanged. See Equation 1.5.
Residual connection
Adding a sub-layer's input directly to its output, creating a gradient "shortcut." See Equation 7.1.
RLHF / RLAIF
Reinforcement Learning from Human (or AI) Feedback — the final training stage that aligns a model's behaviour with human preferences. See Figure 8.1.
RMSNorm
A cheaper alternative to LayerNorm that rescales by root-mean-square without subtracting the mean. See Equation 7.3.
RoPE (Rotary Position Embedding)
Encodes token position by rotating Query/Key vectors by a position-dependent angle. See Equation 5.3.
Router
A small network in a Mixture-of-Experts layer that decides which experts process each token. See Equation 9.1.
SiLU / Swish
A smooth activation function, \(z\cdot\sigma(z)\), underlying SwiGLU. See Equation 1.6.
Softmax
Converts a vector of raw scores into a probability distribution that sums to 1. See Equation 6.2.
Supervised Fine-Tuning (SFT)
The training stage where a pretrained model learns from curated example conversations/instructions. See Figure 8.1.
SwiGLU
A "gated" feed-forward network combining SiLU with an extra multiplicative gate. See Equation 7.6.
Tokenization
Splitting text into the sub-word pieces ("tokens") a model actually processes.
Total parameters
Every weight in a model, including all Mixture-of-Experts experts whether or not they're used for a given token — determines file size on disk.
Transformer
The 2017 architecture built around self-attention (Equation 6.1) that underlies every model in Chapter 10.
Vocabulary
The fixed set of tokens a model can read or output, each with an integer ID. See Equation 3.1.
Weight
A single learnable number controlling how strongly one input influences a neuron, or one entry of a weight matrix. See Equation 1.1 and 2.1.
