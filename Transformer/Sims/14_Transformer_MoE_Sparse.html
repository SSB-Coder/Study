1. Intuition & Architectural Overview

Imagine a classic Dense Transformer as a single, incredibly smart polymath professor. You ask them a question about physics, they answer it. You ask them about poetry, they answer it. To make them smarter, you just give them a bigger brain. But eventually, their brain gets so massive that it takes them hours just to retrieve the information (they run out of compute and VRAM).

A **Sparse Mixture of Experts (MoE)** architecture works like a University instead of a single professor. * **The Experts:** The university has 8 different professors. Professor A specializes in Physics. Professor B specializes in French Poetry. Professor C specializes in Python Coding. * **The Router:** When you walk into the university and ask a question, a receptionist (The Router) looks at your question and says, "Ah, this is a math question. I'll send you directly to Professor A and Professor C."

2. Core Architectural Components

  • **The Experts:** The university has 8 different professors. Professor A specializes in Physics. Professor B specializes in French Poetry. Professor C specializes in Python Coding.
  • **The Router:** When you walk into the university and ask a question, a receptionist (The Router) looks at your question and says, "Ah, this is a math question. I'll send you directly to Professor A and Professor C."

3. Advantages & Trade-Offs

High representational capacity and parameter efficiency, balanced against inductive bias constraints and hardware memory requirements.

Mathematical Formulation & Equations

The following mathematical equations govern the forward pass, loss calculation, and backward pass dynamics visualised in the animation above:

EQUATION 1
$$ G(x) = \text{Softmax}(W_g \cdot x) $$
EQUATION 2
$$ \text{KeepTopK}(v)_i = \begin{cases} v_i & \text{if } v_i \text{ is in the top } K \text{ values of } v \\ -\infty & \text{otherwise} \end{cases} $$
EQUATION 3
$$ G_{sparse}(x) = \text{Softmax}(\text{KeepTopK}(W_g \cdot x)) $$
EQUATION 4
$$ y = \sum_{i=1}^{N} G_{sparse}(x)_i \cdot E_i(x) $$

"""
14. Sparse Mixture of Experts (MoE) Transformers
Deep Dive Implementation

This file demonstrates the MoE architecture used in GPT-5 / DeepSeek.
We explicitly define the Router and implement the Top-K masking logic so that
the model ONLY computes the MLPs for the selected experts, simulating sparsity.
"""

import torch
import torch.nn as nn
import torch.nn.functional as F
class="code-cmt"># Each Expert is a standalone MLP, defined below for full self-containment.

class ExpertMLP(nn.Module):
    """A standard Feed-Forward network acting as a single Professor."""
    class="code-kw">def __init__(self, embed_dim, hidden_dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(embed_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, embed_dim)
        )
    class="code-kw">def forward(self, x):
        return self.net(x)

class ExplicitMoELayer(nn.Module):
    """Replaces the dense MLP with a Router and N Experts."""
    class="code-kw">def __init__(self, embed_dim, hidden_dim, num_experts=8, top_k=2):
        super().__init__()
        self.num_experts = num_experts
        self.top_k = top_k
        
        class="code-cmt"># The Router (The Receptionist)
        self.router = nn.Linear(embed_dim, num_experts, bias=False)
        
        class="code-cmt"># The Experts (The Professors) - stored in a ModuleList
        self.experts = nn.ModuleList([ExpertMLP(embed_dim, hidden_dim) for _ in range(num_experts)])

    class="code-kw">def forward(self, x):
        """
        x: [Batch, Seq_Len, Embed_Dim]
        """
        batch_size, seq_len, embed_dim = x.size()
        
        class="code-cmt"># Flatten sequence for routing: [Batch*SeqLen, Embed_Dim]
        x_flat = x.view(-1, embed_dim)
        
        class="code-cmt"># 1. The Router Output
        class="code-cmt"># Get raw scores for each expert: [Batch*SeqLen, Num_Experts]
        router_logits = self.router(x_flat)
        
        class="code-cmt"># 2. Top-K Selection
        class="code-cmt"># Get the highest K values and their indices
        topk_values, topk_indices = torch.topk(router_logits, self.top_k, dim=-1)
        
        class="code-cmt"># Calculate routing probabilities ONLY for the top K experts using Softmax
        routing_weights = F.softmax(topk_values, dim=-1)
        
        class="code-cmt"># 3. Sparse Expert Computation
        class="code-cmt"># Initialize an empty tensor to hold the final combined output
        final_output_flat = torch.zeros_like(x_flat)
        
        class="code-cmt"># Loop over the K selected slots
        for i in range(self.top_k):
            class="code-cmt"># Which expert was selected for this slot?
            expert_indices = topk_indices[:, i]
            class="code-cmt"># What is the weight for this expert?
            expert_weights = routing_weights[:, i].unsqueeze(1)
            
            class="code-cmt"># Since PyTorch doesn't natively support dynamic graph branching easily without 
            class="code-cmt"># severe overhead in standard loops, we simulate the 'Sparsity' by only 
            class="code-cmt"># calculating the experts that were actually selected by at least one token.
            unique_experts = torch.unique(expert_indices)
            
            for expert_idx in unique_experts:
                class="code-cmt"># Find which tokens chose this specific expert
                token_mask = (expert_indices == expert_idx)
                
                if token_mask.any():
                    class="code-cmt"># Extract only the tokens that go to this expert
                    tokens_for_expert = x_flat[token_mask]
                    
                    class="code-cmt"># RUN THE EXPERT (This is the compute-saving step! Other experts sleep)
                    expert_out = self.experts[expert_idx](tokens_for_expert)
                    
                    class="code-cmt"># Multiply by the router's confidence weight and add to final output
                    weights_for_tokens = expert_weights[token_mask]
                    final_output_flat[token_mask] += expert_out * weights_for_tokens

        class="code-cmt"># Unflatten back to sequence shape
        final_output = final_output_flat.view(batch_size, seq_len, embed_dim)
        return final_output
