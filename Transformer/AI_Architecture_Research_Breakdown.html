Section 02 · Theoretical & Engineering Critique

Structural Bottlenecks of Present SOTA Transformers

The Transformer has dominated AI since 2017, but it is burdened by fundamental architectural choices that create hard physical ceilings. Understanding these bottlenecks precisely is the prerequisite to replacing them.

The Quadratic Attention Wall

Complexity: O(N²) time · O(N²) space

The core self-attention operation computes the score matrix \( QK^T \in \mathbb{R}^{N \times N} \) which scales quadratically with sequence length \( N \). For a single attention head:

\[ \text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^T}{\sqrt{d_k}}\right)V \]

For a model with \( L \) layers, \( H \) heads, hidden dimension \( d \), and sequence length \( N \):

  • FLOPs per forward pass: \( O(LHN^2d) \)
  • Memory for attention scores: \( O(LHN^2) \) — this is the critical constraint

At \( N = 128{,}000 \) tokens (a typical long-context model), the raw attention matrix has \( 128{,}000^2 \approx 1.6 \times 10^{10} \) entries. At float32 precision, that's ~64 GB per head per layer — physically impossible on any single GPU. This is why FlashAttention (which keeps the attention matrix in fast SRAM by tiling) became mandatory, not optional.

Technical Precision

FlashAttention doesn't change the algorithmic complexity — it's still O(N²) in FLOPs. What it does is radically reduce HBM read/write operations from \( O(N^2) \) to \( O(N) \) by computing attention in tiled SRAM blocks. The bottleneck shifts from compute to memory bandwidth, and FlashAttention resolves the bandwidth bottleneck at the cost of greater arithmetic intensity.

The KV Cache Memory Wall

Memory: O(L · N · 2d) bytes per sequence

During autoregressive generation, a Transformer decodes one token at a time. To avoid recomputing the Key and Value tensors for all previous tokens at each step, they are cached in GPU HBM. For a model with \( L \) layers, hidden dimension \( d \), and \( H \) heads, each token adds:

\[ \text{KV Cache per token} = 2 \times L \times d \times \text{sizeof(dtype)} \]

For Llama-3.1-70B (\( L = 80, d = 8192 \)) in BF16 (2 bytes): each generated token costs 2.6 MB of KV cache. A 128K context uses ~334 GB — nearly 5× the VRAM of an H100 80GB card.

  • GQA (Grouped-Query Attention): Reduces KV heads from \( H \) to \( G \ll H \). Llama-3 uses \( G=8 \) vs \( H=64 \), giving an 8× reduction.
  • MLA (Multi-Head Latent Attention): DeepSeek-V2 compresses KV to a low-rank joint matrix \( c^{KV} \in \mathbb{R}^{d_c}, d_c \ll d \), achieving a 93% cache reduction.
  • PagedAttention (vLLM): Manages KV cache like virtual memory, allowing non-contiguous blocks and radical improvement in serving throughput.

Autoregressive Decoding Latency

Throughput: 1 token per forward pass · Memory-bandwidth bound

Transformer generation is sequential: token \( t \) cannot be produced until token \( t-1 \) is finished. This creates a fundamental latency floor. Worse, during decoding, the model is memory-bandwidth bound rather than compute-bound — the GPU spends most of its cycles moving parameters from HBM into SRAM, not doing arithmetic.

Arithmetic Intensity during generation: \( \approx \frac{\text{FLOPs per token}}{\text{bytes moved}} \ll \) the roofline for compute-optimal usage. For a 70B model generating one token, the GPU achieves <5% of its theoretical FLOP/s utilization.

Speculative Decoding (Leviathan et al., 2023) partially resolves this by using a small draft model to propose \( k \) candidate tokens in parallel, which the large target model then accepts or rejects in a single forward pass — giving \( 2–3\times \) real-world speedup with guaranteed identical output distribution.

Fixed Context & "Lost in the Middle" Degradation

Retrieval degrades at positions away from the endpoints of the context window

Even with extended context windows (128K–2M tokens), Transformers exhibit a documented U-shaped recall curve: information placed at the very beginning or very end of a long context is retrieved reliably, but information buried in the middle is catastrophically degraded. This is an emergent consequence of softmax attention's distributional properties — the exponential scoring means a few dominant tokens attract nearly all the probability mass.

Mathematically: with \( N \) tokens, the softmax normalization is

\[ \text{softmax}(q_i k_j^T / \sqrt{d_k})_j = \frac{e^{q_i k_j^T/\sqrt{d_k}}}{\sum_{j'} e^{q_i k_{j'}^T/\sqrt{d_k}}} \]

When \( N \) is large, the denominator is dominated by a handful of extreme values, making it statistically near-impossible for the model to "focus" on a middle-position token unless it has an extraordinarily high query-key alignment score.

Positional encoding also becomes brittle. Standard sinusoidal encodings and naive RoPE extrapolate poorly beyond the training context length. NTK-aware RoPE, YaRN, and LongRoPE are engineering patches, not solutions to the underlying distributional problem.

Reasoning Deficiencies & System 2 Absence

Core issue: fixed compute budget proportional only to sequence length, not problem complexity

Standard Transformers are constant-depth at inference: each forward pass executes exactly \( L \) layers regardless of whether the input is "What is 2+2?" or "Prove the Riemann Hypothesis." The model cannot "think harder." This is Kahneman's System 1 (fast, associative) without System 2 (slow, deliberate). Consequences:

  • Hallucinations: Transformers are next-token probability maximizers. When a statistically plausible but factually wrong continuation exists, the model will generate it confidently. There is no internal verification step.
  • Mathematical failures: Multi-step arithmetic, symbolic manipulation, and proof steps require exact computation. Approximate pattern-matching produces compounding errors across steps.
  • Planning horizon: Transformers have no persistent working memory across a plan. Each decoding step conditions on the entire prior context, but the "scratchpad" is simply the generated token stream — there is no structured intermediate representation.

The partial solution is test-time compute (OpenAI o1, DeepSeek-R1): generate a chain-of-thought "thinking trace" before the answer. This allocates more compute by generating more tokens, but does not change the fundamental constant-depth architecture per forward pass.

Training Instability & Catastrophic Forgetting

Continual learning is fundamentally unsolved in dense Transformers

Transformer weights encode knowledge via the same parameters that process every input. When fine-tuned on new data, the model overwrites previously learned associations — catastrophic forgetting — unless techniques like replay buffers, EWC (Elastic Weight Consolidation), or LoRA adapters are used. There is no structural separation between working memory, short-term memory, and long-term factual storage, unlike the brain's hippocampus-neocortex system.

Additionally, training at scale is brittle: attention entropy collapse, gradient explosions in deep stacks, and loss spikes during continued pre-training are active research problems. Modern solutions include QK-Norm (stabilizing attention logits), Z-loss regularization, and μP (maximal update parameterization) initialization.

State Space Models: Mamba & Mamba-2

Mamba / Mamba-2 (Selective SSM) O(N) 2023 / 2024

The breakthrough in Mamba (Gu & Dao, 2023) was data-dependent SSM parameters. Classic S4 had fixed \( A, B, C \) matrices — they couldn't selectively filter irrelevant tokens. Mamba makes \( B \), \( C \), and the discretization step \( \Delta \) functions of the current input \( x_t \), giving the model a learned forget gate analogous to an LSTM. Mamba-2 (2024) restructured this as a Semi-Separable Matrix Multiplication, enabling larger state dimensions and improved GPU parallelism via a "state space duality" connection to linear attention.

Strengths

  • True O(1) memory at inference — the fixed-size state replaces the KV cache entirely
  • Linear scaling in training via parallel scan or convolution view
  • Strong performance on long-range DNA, audio, and time-series tasks
  • Can use 10–20× longer contexts at same memory budget vs Transformer

Weaknesses

  • Compressed state cannot perform exact retrieval — "needle in a haystack" fails at long range
  • Expressivity limited by state dimension \( d_{\text{state}} \); large states recover cost
  • Currently underperforms dense Transformers on standard language benchmarks at equivalent scale
  • Custom CUDA kernels required for competitive speed (not pure PyTorch)

Linear Attention Mechanisms

GLA / FlashLinearAttention / HGRN2 O(N) 2023–2024

Linear attention replaces softmax with a kernel function \( \phi \) and reorders computation from \( \text{softmax}(QK^T)V \) to \( Q(\phi(K)^T V) \), shifting from \( O(N^2) \) to \( O(Nd^2) \). Gated Linear Attention (GLA, Yang et al., 2024) added data-dependent gates, recovering much of Mamba's expressivity within the linear attention framework. FlashLinearAttention (Sun et al., 2024) provided the hardware-efficient chunked training algorithm. The key advantage over SSMs: linear attention retains the conceptual similarity to Transformer attention, making architectural ablations and hybrid construction more natural.

Strengths

  • Conceptual continuity with Transformer attention — easier to hybridize
  • Recurrent form enables O(1) inference memory
  • GLA's gating catches up to Mamba on most benchmarks

Weaknesses

  • Kernel approximation \( \phi \) introduces approximation error — no longer exact
  • Still weaker than softmax attention on retrieval and in-context learning tasks
  • Quadratic \( O(d^2) \) state dimension can be expensive at large head dims

RWKV: Receptance Weighted Key Value

RWKV (v4/v5/v6) O(N) 2023

RWKV (Peng et al., 2023) is a 100% RNN at inference but is parallelizable during training via a custom WKV operator computed in log-space for numerical stability. It replaces QKV projection with receptance (R), weight (W, a time-decay vector), key (K), and value (V) interactions — achieving pure linear-time inference with no KV cache at all. RWKV-6 introduced data-dependent recurrence, closing much of the performance gap to Transformers. It is fully open-source (RWKV-5-World trained on 100+ languages).

Strengths

  • Zero KV cache — constant memory per token regardless of context
  • Proven at large scale (14B parameter models exist and perform competitively)
  • Architecturally simple — no complex kernel tricks

Weaknesses

  • Time-decay limits long-range recall (exponential forgetting baked in)
  • In-context learning (few-shot prompting) significantly weaker than Transformers
  • Parallel scan efficiency lower than SSMs with dedicated GPU kernels

xLSTM: Extended Long Short-Term Memory

xLSTM (mLSTM / sLSTM) O(N) · O(d²) state 2024

Beck et al. (2024) revisited LSTM with two critical innovations: sLSTM adds exponential gating (replacing sigmoid gates with exp functions) for better stability, and mLSTM replaces the scalar memory cell with a matrix memory \( C_t \in \mathbb{R}^{d_h \times d_h} \), giving it \( O(d^2) \) storage capacity vs the O(d) of standard LSTMs. This matrix memory enables significantly better retrieval. Competitive with Mamba on language modeling while bringing LSTM-style interpretability.

Strengths

  • Matrix memory improves associative recall dramatically
  • Exponential gating allows much longer gradient highways
  • Better in-context learning than pure SSMs

Weaknesses

  • Matrix memory \( O(d^2) \) is expensive at large dims
  • Still nascent ecosystem — no large-scale (70B+) validated models yet

Titans: Neural Long-Term Memory

Titans (Google DeepMind, 2024) O(N) persistent + O(N²) local window 2024

Titans (Ali et al., 2024) introduces a neural memory module with three memory systems mimicking human cognition: (1) a persistent memory (learned parameters as long-term knowledge), (2) a long-term memory (neural network that updates weights at test-time via gradient descent on individual sequences), and (3) a short-term memory (sliding window attention for immediate context). The long-term memory module performs surprise-driven updates — tokens that violate the current model's prediction update the memory more aggressively. This is the most structurally ambitious architecture of 2024–2025 and shows state-of-the-art needle-in-a-haystack performance.

Strengths

  • Best retrieval at long range of any linear-complexity architecture
  • Test-time learning — adapts to the specific input sequence
  • Architecturally inspired by human memory systems

Weaknesses

  • Test-time gradient steps add latency overhead
  • Most complex to implement of all alternatives
  • Not yet validated at frontier scale (100B+)

The Hybrid Consensus

The current research consensus (2025–2026) is converging on hybrid architectures: interleave SSM/linear-RNN layers for long-range efficiency and a sparse set of full-attention layers for precision retrieval. Models like Jamba (Mamba + Transformer), Zamba-2, and Hymba achieve near-Transformer quality at 3–5× lower inference cost. Designing a better hybrid — with a principled theory of when to use which primitive — is the most tractable research direction.

Section 04 · Mandatory Reading List

Curated Research Syllabus

80 papers distilled to the ~40 that are genuinely essential. Read them in order. Each entry states the exact architectural insight it introduces and why skipping it will leave a specific gap in your capability.

Tier 1 — Absolute Foundations (Read First)

Foundation

Attention Is All You Need

Vaswani et al., 2017 · Google Brain · arXiv:1706.03762

The original Transformer. Read the full paper, not a blog post. Understand encoder-decoder structure, multi-head attention, positional encodings, and why "all you need" was deliberate hyperbole. Every subsequent paper modifies something from this one.

Foundation

BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding

Devlin et al., 2018 · Google · arXiv:1810.04805

Introduces masked language modeling (MLM) and the distinction between encoder-only and decoder-only pre-training paradigms. Establishes that pre-training + fine-tuning is the dominant training strategy.

Foundation

Language Models are Few-Shot Learners (GPT-3)

Brown et al., 2020 · OpenAI · arXiv:2005.14165

Establishes in-context learning as an emergent property of scale. The paper that demonstrated that massive decoder-only models, without any fine-tuning, can perform tasks via prompt engineering. Defines the modern LLM paradigm.

FoundationScaling

Scaling Laws for Neural Language Models

Kaplan et al., 2020 · OpenAI · arXiv:2001.08361

Establishes the power-law relationship between loss, parameters, data, and compute. Every resource allocation decision during architecture development is governed by these laws. Cannot be skipped.

FoundationScaling

Training Compute-Optimal Large Language Models (Chinchilla)

Hoffmann et al., 2022 · DeepMind · arXiv:2203.15556

Revised Kaplan's scaling laws and showed GPT-3 was massively undertrained. The Chinchilla optimal formula \( N \propto C^{0.5},\, D \propto C^{0.5} \) governs how to allocate compute between model size and tokens. Essential before designing any training run.

Efficiency

FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness

Dao et al., 2022 · Stanford · arXiv:2205.14135

Arguably the most practically impactful paper of the decade. Read the actual algorithm — the tiling approach, the online softmax, the fused backward pass. Any novel attention variant must implement equivalent IO-awareness or it will be 10× slower in practice. Understand the roofline model before reading.

Efficiency

FlashAttention-2: Faster Attention with Better Parallelism and Work Partitioning

Dao, 2023 · Princeton · arXiv:2307.08691

Rewrites the tiling strategy for better warp-level parallelism. Introduces the critical insight about thread block scheduling that achieves ~2× speedup over FA-1. Needed for understanding modern GPU kernel design.

Tier 2 — Architecture Deep Dives (Core Research Knowledge)

Architecture

Efficiently Modeling Long Sequences with Structured State Spaces (S4)

Gu et al., 2021 · Stanford · arXiv:2111.00396

The mathematical foundation of all SSMs. Introduces HiPPO theory — the principled method of initializing the state matrix \( A \) for optimal long-range memory. The convolution equivalence proof is the key technical insight. Mamba is incomprehensible without reading this first.

SSM

Mamba: Linear-Time Sequence Modeling with Selective State Spaces

Gu & Dao, 2023 · Carnegie Mellon/Princeton · arXiv:2312.00752

The primary SSM paper. Master the selective scan algorithm, the data-dependent parameterization, and the hardware-aware parallel scan. This is the "Attention Is All You Need" of the recurrent approach.

SSM

Transformers are SSMs: Generalized Models and Efficient Algorithms Through Structured State Space Duality (Mamba-2)

Dao & Gu, 2024 · arXiv:2405.21060

Establishes that Mamba and linear attention are two instances of the same mathematical framework (structured matrix multiplication). Opens the design space for principled hybrid construction. Critical for original research.

RWKV

RWKV: Reinventing RNNs for the Transformer Era

Peng et al., 2023 · EleutherAI · arXiv:2305.13048

Shows how to design a linear RNN that is parallelizable during training but runs as a pure RNN at inference. The WKV operator and time-mixing / channel-mixing decomposition are important design patterns.

Retention

Retentive Network: A Successor to Transformer for Large Language Models (RetNet)

Sun et al., 2023 · Microsoft Research · arXiv:2307.08621

Introduces the "retention" mechanism — a generalization of attention with an explicit exponential time-decay, enabling parallel, recurrent, and chunked computation modes. Important for understanding the design space between SSMs and full attention.

Linear Attn

Gated Linear Attention Transformers with Hardware-Efficient Training

Yang et al., 2023 · MIT / Stanford · arXiv:2312.06635

The most competitive linear attention formulation. Shows that adding scalar data-dependent gates to linear attention closes most of the gap with softmax attention on language tasks. Essential for understanding the linear attention sub-field.

Convolution

Hyena Hierarchy: Towards Larger Convolutional Language Models

Poli et al., 2023 · Stanford · arXiv:2302.10866

Replaces attention entirely with long implicit convolutions. Demonstrates attention-free sequence modeling at language scale. Important for the subquadratic design vocabulary.

Hybrid

Jamba: A Hybrid Transformer-Mamba Language Model

Lieber et al., 2024 · AI21 Labs · arXiv:2403.19887

First major validated hybrid architecture. Shows the specific Mamba/Attention interleaving ratios that achieve near-Transformer quality at significantly reduced KV cache. Provides the experimental blueprint for hybrid architecture research.

Neural Memory

Titans: Learning to Memorize at Test Time

Ali et al., 2024 · Google · arXiv:2501.00663

The most architecturally novel paper of 2024–2025. Introduces a neural long-term memory module that updates at test time via surprise-driven gradient steps. Read for the design philosophy — this is the direction toward continual learning.

xLSTM

xLSTM: Extended Long Short-Term Memory

Beck et al., 2024 · JKU Linz · arXiv:2405.04517

Brings LSTMs into the modern era with matrix memory cells and exponential gating. The mathematical proof that matrix memory enables exact key-value retrieval (unlike compressed state vectors) is architecturally important.

KAN

KAN: Kolmogorov-Arnold Networks

Liu et al., 2024 · MIT/Caltech · arXiv:2404.19756

Proposes replacing MLP weights with learnable splines on edges. Critical for understanding the design space beyond matrix multiplication. The interpretability and anti-catastrophic-forgetting properties are practically interesting for novel architectures.

Tier 3 — Efficiency & Training

GQA

GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints

Ainslie et al., 2023 · Google · arXiv:2305.13245

Introduces Grouped-Query Attention — the KV cache reduction trick now used in every major open-source model (Llama-3, Mistral, Qwen). Understand the trade-off between KV cache size and model expressivity.

MLA

DeepSeek-V2: A Strong, Economical, and Efficient Mixture-of-Experts Language Model

DeepSeek Team, 2024 · arXiv:2405.04434

Introduces Multi-Head Latent Attention (MLA) — compressing the KV cache 93% via low-rank projection. Also introduces DeepSeekMoE with fine-grained expert segmentation. Arguably the most engineering-rich open paper of 2024.

Speculative

Fast Inference from Transformers via Speculative Decoding

Leviathan et al., 2023 · Google · arXiv:2211.17192

The accepted proof that speculative decoding produces samples from the exact target distribution. Essential for understanding inference-time acceleration.

Quantization

GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers

Frantar et al., 2022 · IST Austria · arXiv:2210.17323

The dominant weight quantization method for LLMs. Any new architecture needs a quantization story. Understand the second-order gradient approximation used for weight compression.

Positional Enc

RoFormer: Enhanced Transformer with Rotary Position Embedding (RoPE)

Su et al., 2021 · arXiv:2104.09864

RoPE is now the default positional encoding in virtually every modern model. It encodes positions by rotating Q/K vectors in complex number space, enabling elegant context extension via NTK-aware scaling. Must-know.

Distributed

Ring Attention with Blockwise Transformers for Near-Infinite Context

Liu et al., 2023 · UC Berkeley · arXiv:2310.01889

Shows how to distribute a 1M+ token context across multiple GPUs by passing K,V blocks in a ring topology with overlapping compute and communication. Essential for understanding multi-GPU long-context training.

MoE

Outrageously Large Neural Networks: The Sparsely-Gated Mixture-of-Experts Layer

Shazeer et al., 2017 · Google Brain · arXiv:1701.06538

The original MoE paper in the deep learning era. Defines the Top-K gating, load balancing loss, and the engineering constraints. All subsequent MoE papers (Switch Transformer, Mixtral, DeepSeek-V3) reference this.

Token-free

Byte Latent Transformer: Patches Scale Better Than Tokens

Pagnoni et al., 2024 · Meta AI · arXiv:2412.09871

Eliminates tokenization entirely. Operates on raw bytes grouped into dynamic patches. Demonstrates that the standard BPE tokenization bottleneck is not fundamental — a major architectural insight for next-gen models.

Tier 4 — Alignment, Reasoning & Training Methods

RLHF

Training Language Models to Follow Instructions with Human Feedback (InstructGPT)

Ouyang et al., 2022 · OpenAI · arXiv:2203.02155

Establishes the SFT → Reward Model → PPO training pipeline. The RLHF recipe that made ChatGPT possible. Understanding PPO (Proximal Policy Optimization) mathematically is required.

DPO

Direct Preference Optimization: Your Language Model is Secretly a Reward Model

Rafailov et al., 2023 · Stanford · arXiv:2305.18290

Shows that RLHF's reward model and RL loop can be collapsed into a single supervised fine-tuning objective. DPO is now the dominant alignment method. The derivation from the RLHF objective is mathematically elegant.

Chain-of-Thought

Chain-of-Thought Prompting Elicits Reasoning in Large Language Models

Wei et al., 2022 · Google Brain · arXiv:2201.11903

Demonstrates that eliciting intermediate reasoning steps (CoT) dramatically improves performance on math and logic tasks. The paper that triggered the "reasoning model" era. Understand why CoT works from a computational complexity perspective.

Test-Time Compute

Scaling LLM Test-Time Compute Optimally Improves Performance (DeepMind)

Snell et al., 2024 · UC Berkeley · arXiv:2408.03314

Proves that there exists an optimal allocation of test-time compute (more for hard questions, less for easy ones). The mathematical framework for adaptive compute in inference — the backbone of o1/R1-class models.

RL Reasoning

DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning

DeepSeek Team, 2025 · arXiv:2501.12948

Shows that pure RL (GRPO, without SFT warmup) can elicit sophisticated mathematical reasoning. The "aha moment" training dynamic and the emergent chain-of-thought are phenomena that any future reasoning architecture must account for.

Interpretability

Scaling Monosemanticity: Extracting Interpretable Features from Claude 3 Sonnet

Templeton et al., 2024 · Anthropic

Demonstrates that Sparse Autoencoders (SAEs) can decompose Transformer MLP activations into interpretable, human-understandable features at scale. Mechanistic interpretability is becoming a design constraint, not just an analysis tool.

Section 05 · Technical Research Framework

Engineering Roadmap for a Novel Paradigm

This is the step-by-step process a well-funded AI research lab uses to move from "I have a new idea" to "this paper is published and the model is running." It applies equally to a solo researcher working at smaller scale.

Phase 0 — Prerequisite Knowledge Stack

0A

Mathematics: Fill Your Gaps First

Before writing a single line of novel architecture code, address the mathematical prerequisites identified in Section 1. The sequence is non-negotiable:

  • Linear Algebra: Strang's MIT OCW lectures or "Introduction to Linear Algebra" (Strang, 5th ed.). Focus on SVD, eigenvectors, and the four fundamental subspaces.
  • Multivariable Calculus + Optimization: Boyd's "Convex Optimization" (free at stanford.edu). Understand gradient descent convergence proofs, saddle points, and loss landscape structure.
  • Probability & Bayesian Inference: Bishop's "Pattern Recognition and Machine Learning" Ch. 1–3, 8–9. Learn the variational inference derivation from scratch.
  • Information Theory: Cover & Thomas "Elements of Information Theory" — Shannon entropy, KL divergence, mutual information. Read Ch. 1–4.
  • Fourier Analysis: Oppenheim's "Signals & Systems" — understand the convolution theorem and why FFT is O(N log N). Needed for SSMs.
0B

Systems: Learn to Write GPU Kernels

Architecture research without kernel programming is decoration. Two paths:

  • Triton (Recommended): Read the official Triton tutorials. Implement a fused softmax, then a basic attention kernel. Triton compiles to PTX/SASS automatically. Target: 2–3 weeks to write a working FlashAttention-equivalent.
  • CUDA (For deeper control): Nvidia's "CUDA C++ Programming Guide." Understand thread hierarchy (thread → warp → block → grid), shared memory banks, memory coalescing. Use ncu (Nsight Compute) to profile every kernel you write.
  • Study the FlashAttention CUDA source on GitHub — specifically the backward pass — to understand fused gradient computation.

Phase 1 — Identify Your Research Hypothesis

01

Formalize the Bottleneck You Are Solving

A novel architecture paper must make a falsifiable claim of the form: "Current architecture X fails to solve property Y because of mechanism Z. My architecture replaces Z with W, which provably/empirically achieves Y."

Map your hypothesis to one of the axes below:

  • Computational efficiency axis: Sub-quadratic complexity that matches Transformer quality on standard benchmarks
  • Memory efficiency axis: Constant or sub-linear inference memory without retrieval degradation
  • Reasoning depth axis: Adaptive compute budget per problem complexity without sacrificing speed on simple tasks
  • Continual learning axis: Weight updates that incorporate new information without catastrophic forgetting
  • Sample efficiency axis: Better performance per training token — requires better inductive biases or world model integration

Phase 2 — Hardware-Aware Design Principles

02

Design Around the Memory Hierarchy First

Before designing your operation mathematically, understand the GPU memory hierarchy. On an H100 SXM:

H100 Memory Hierarchy: ├── SRAM (L1/Shared Memory): ~256 KB per SM · ~19 TB/s bandwidth ├── L2 Cache: 50 MB shared · ~3.35 TB/s └── HBM3 (Global Memory): 80 GB · ~3.35 TB/s The compute-to-memory-bandwidth ratio (roofline): H100 FP16 peak: ~1979 TFLOP/s H100 HBM bandwidth: 3.35 TB/s → Operations with arithmetic intensity > 590 are compute-bound. → Most attention operations during decoding are memory-bound.

The rule: any operation you design must maximize SRAM reuse and minimize HBM round-trips. This is the FlashAttention principle, and it applies to every new primitive. Ask: "How many bytes do I move per FLOP?" If < 590 bytes/FLOP on H100, you are memory-bound and must fuse operations.

03

Design the Mathematical Primitive

Your novel architecture's core contribution must be a new computational primitive that:

  • Has a recurrent form for efficient inference (O(1) memory per step if possible)
  • Has a parallel form for training (via parallel scan, FFT convolution, or chunked computation)
  • Is IO-aware — the parallel training form maps to a SRAM-tiled kernel, not a naive O(N²) HBM read
  • Has expressive data-dependent parameters — purely time-invariant models (classic SSMs) fail on selective tasks

The most productive design space right now: generalize the structured matrix product. Mamba-2 showed that both linear attention and SSMs are instances of Semi-Separable Matrix products. New models can be designed by varying the structure of this matrix (block-diagonal, Toeplitz, causal convolutional) to achieve different expressivity/efficiency trade-offs.

Phase 3 — Implementation Protocol

04

Prototype at Scale 1: Tiny Models on Toy Tasks

Before running GPU clusters, validate your mathematical primitive on toy sequence memorization tasks. Critical test suite:

  • Selective Copy Task: Given a sequence with marked elements, copy only the marked ones. SSMs with non-selective parameters fail this. Validates data-dependency.
  • Associative Recall: "Key A → Value B" pairs presented, then query "What is A?" Tests key-value storage in state.
  • Needle in a Haystack: A synthetic "retrieve fact X from position P in 100K tokens" benchmark. Differentiates pure SSMs from hybrid/attention models.
  • Induction Heads: "(A)(B)...(A)?" — model must predict B. Standard test for in-context learning capability.

Run these at model sizes of ~10M–100M parameters. If your primitive fails selective copy, it will fail everything.

05

Write the Custom Triton Kernel

Once the mathematical primitive is validated, write the hardware kernel. The workflow:

  • Start with a naive PyTorch reference implementation (correct but slow)
  • Profile with torch.profiler to identify memory-bound vs compute-bound regions
  • Write the Triton kernel: implement tiled computation so the hot inner loop fits in SRAM
  • Verify correctness with gradient checking: torch.autograd.gradcheck
  • Benchmark with triton.testing.do_bench and compare to the naive baseline and FlashAttention
  • Target: your kernel should reach ≥70% of the theoretical memory bandwidth on H100
06

Scale 2: 1B Parameter Ablation Study

The standard evaluation protocol for sequence model papers:

  • Language modeling perplexity on The Pile or RedPajama at equivalent training FLOPs to a Transformer baseline
  • Common benchmarks: HellaSwag, PIQA, ARC-Easy/Challenge, WinoGrande, LAMBADA — standard zero-shot tasks
  • Long-context tasks: RULER (which specifically includes needle-in-haystack at various depths), LongBench
  • Throughput benchmarks: Tokens/second at various sequence lengths vs Transformer and Mamba baselines
  • Memory footprint: Peak GPU memory during training and inference at N = 4K, 16K, 64K, 256K tokens

If you cannot beat or match Mamba at equivalent compute at 1B scale, revisit the primitive before scaling further.

Phase 4 — Structural Mechanisms for Superior Performance

07

The Five Design Levers You Must Address

Every novel architecture research paper must make deliberate choices on these axes:

  1. State Expansion: How does the hidden state \( h_t \) scale with model size? Linear (RWKV) vs matrix (xLSTM) vs structured (SSM) — each trades parameter count for expressivity differently.
  2. Gating Mechanism: Data-dependent gates (as in Mamba's \( \Delta, B, C \)) are critical for selectivity. Without them, the model cannot filter irrelevant tokens. Design your gate to be input-dependent but computation-light.
  3. Positional Bias: How does your model encode position? Learned recurrence (implicit in SSMs), explicit RoPE injection, or alibi-style biases? Models without any position bias extrapolate better but lose ordering signals.
  4. Hybridization Strategy: At what layer frequency do you insert full attention "checkpoints"? Research suggests every 4–8 linear layers benefits from one attention layer for precision retrieval, with diminishing returns after that.
  5. Normalization Placement: Pre-norm (RMSNorm before the sublayer, as in modern models) vs post-norm vs sandwich norm. Pre-norm with RMSNorm is currently the most stable configuration — do not deviate without strong experimental justification.
08

Achieving Infinite Context Without Retrieval Degradation

This is the unsolved problem — the single most important research target. The current best approaches:

  • Sparse Attention Windows + Global Memory: Full attention over a local window (e.g., 4K tokens) + a compressed representation of the full history. Titans-style neural memory achieves this but with test-time gradient steps.
  • Hierarchical State Compression: Multi-scale SSM layers where lower layers compress raw tokens and higher layers operate on the compressed representations. Similar to human memory's episodic-to-semantic consolidation.
  • Differentiable Key-Value Memory Banks: External memory with learned read/write heads (differentiable neural computers). The challenge is making the routing efficient enough to not bottleneck throughput.
  • The open question: Is there a mathematical operation that achieves O(1) inference memory AND exact retrieval? Current theory suggests this requires at least O(N) state in the worst case. A counterexample would be a significant theoretical contribution.

Phase 5 — Distributed Training Setup

09

Multi-GPU Training for Models >7B Parameters

Beyond 7B parameters, single-GPU training is impossible. Master these parallelism strategies before your first large run:

  • Data Parallelism (DP/DDP): Each GPU holds a full model copy, processes different batches, and synchronizes gradients via all-reduce. Scales easily but requires all weights to fit on one GPU.
  • Tensor Parallelism (TP): Shard individual weight matrices across GPUs. Each GPU holds 1/N of each layer. Used within a node (NVLink bandwidth critical). Megatron-LM is the standard implementation.
  • Pipeline Parallelism (PP): Different layers on different GPUs (or machines). GPUs pass activations between stages via point-to-point communication. GPipe and 1F1B scheduling avoid the "pipeline bubble" problem.
  • ZeRO Optimizer (DeepSpeed): Shards optimizer states (Stage 1), gradients (Stage 2), and parameters (Stage 3) across GPUs. ZeRO-3 allows training a 70B model on 8× H100 with no model parallelism complexity.
  • Sequence Parallelism (SP) / Ring Attention: Required for context lengths >128K. Shard the sequence dimension across GPUs. All-gather K,V in a ring during attention computation.

Phase 6 — The Publication & Open Source Path

10

From Experiment to Paper

A publishable novel architecture paper needs:

  • A clean theoretical contribution: a new primitive with mathematical analysis of its complexity and expressivity
  • A hardware-aware implementation: a Triton/CUDA kernel that matches or beats FlashAttention in throughput
  • Rigorous ablations at small scale (125M–1B) showing that each design choice matters
  • Scaling experiments: show that the quality gap to Transformers narrows or closes as compute increases
  • Long-context benchmarks: RULER, LongBench, or a new benchmark that specifically tests your architecture's claimed advantage
  • Open-source code on GitHub with a detailed README and reproducible training scripts

Target venues: NeurIPS, ICML, ICLR (architecture track), or arXiv preprint. The fastest path to credibility is an arXiv preprint with open-source code before conference submission.

Recommended Starting Point for Blant Specifically
